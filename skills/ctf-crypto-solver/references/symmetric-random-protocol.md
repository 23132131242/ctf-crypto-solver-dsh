# 对称密码、随机数与协议

## 对称加密

- 核对算法、模式、块大小、IV/nonce 长度、填充、tag、AAD、编码与端序；同 Key 下只比较确实相同的 nonce/计数器区间。
- AES/3DES/DES ECB 的相同块泄漏只证明模式特征，不自动恢复明文。CBC Bit Flipping 需验证改动落在哪一块；CBC Padding Oracle 需可区分填充反馈及用户授权的挑战 oracle；CTR/ChaCha20/Salsa20 nonce 重复时先验证 keystream 重用，再用已知明文/crib 推导，检查计数器布局。
- XOR：对单字节、多字节/重复 Key 建立长度、频率、可打印比例与已知明文证据；对双密文异或仅能得到 `P1 xor P2`，不能凭此单独认定明文。DES 弱密钥、双重 DES meet-in-the-middle、差分/线性分析需明确轮数、数据量、模式和复杂度，不承诺对标准全轮实现有效。
- 对自定义流密码追踪初始化、更新、密钥和 nonce 注入、状态转移、输出函数；需要时以测试向量确认逆向推导。正确认证加密的 tag 失败即拒绝该候选，不静默忽略完整性错误。

## 随机数

- 收集原始输出、输出顺序/截断方式、已知种子范围和是否跨进程重置。LCG 由 `x_(i+1) = a*x_i+b mod m` 建立同余；未知模数时由相邻差的交叉关系提候选并再验证独立输出。
- MT19937/Python random 只有在拿到足量连续且可复原的 32 位输出和正确状态对齐时才能谈 untemper 状态恢复；Java Random 需区分 `nextInt`、`nextLong` 等不同 API 的位提取；xorshift/LFSR 可由线性方程或 Berlekamp-Massey 建模，NLFSR 与 BBS 不可简单套用线性恢复。
- 时间种子尝试仅在题面提供可信时间窗时做有界检索，并用未参与拟合的输出验证。短输出、跳样、舍弃值、混入加密变换时先写明不可辨识因素。

## 协议、链上与零知识

- Diffie-Hellman/ECDH 核对生成元阶、参数验证、公钥/曲线点检查与 KDF；MITM、弱群、小子群/Invalid Curve 仅在隔离或明确授权的挑战服务中验证。
- 认证、Padding、重放与挑战响应题要描述攻击者实际控制的输入、可观察的输出、oracle 假设及查询预算；真实系统不可操作。
- Bitcoin/Ethereum 题先从题目提供的交易数据提取签名的 r,s 和正确 z，再核对同密钥、链 ID、签名规范、低 s 变体、交易编码；重复 r 不等于自动同一密钥。Merkle Tree 检查树顺序与证明路径。
- 零知识证明题明确公共输入、见证、承诺、挑战与响应；检查 Fiat-Shamir 域分离、重复随机数、非规范输入、约束缺失与电路范围；先构造本地反例，再讨论漏洞。
